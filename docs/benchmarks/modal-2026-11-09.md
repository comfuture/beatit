The private [Beatit Modal app](https://modal.com/apps/comfuture/main/deployed/beatit)
was deployed to `comfuture/main` and completed two real full-track transcriptions.
Authentication was verified, service credentials were stored in the Git-ignored

Machine-readable evidence: [modal-2026-11-09.json](modal-2026-11-09.json).

## Published runtime

The app now references this named image with `modal.Image.from_name(...)`:

```text
beatit-processing:py312-cu128-volume-8e06b89eeb19-v1
im-ecJN06c4l8KRQMWJqpvJhv
```

The dependency recipe and explicit build/publish operation live in
`scripts/build_modal_image.py`; app deployments only resolve the name and mount the
current application source. Publishing the already built image took 4.411 seconds.
The named-image deployment reported 2.809 seconds and performed no image build.
The published, deployed, and benchmarked image IDs were checked to be identical.

The original implementation already reused Modal's cached image layers. Named
publication adds an explicit version boundary and prevents an app deployment from
executing the dependency/model build recipe. It does not change this image's binary
contents or imply a different inference speed.

## Full-track first/repeat comparison

Both runs used the same 275.121-second source file, identical SHA-256 and options,
T4 GPU, 2 requested CPU cores, 8 GiB requested memory, Verovio, and enabled tom
refinement. The model Volume had already been populated on CPU. Neither run reused
a previous inference result. Each condition has one observation.

| Measurement | First full transcription | Repeat full transcription |
| --- | ---: | ---: |
| Client worker wall, through import and cleanup | 153.468 s | 147.628 s |
| Client model-preparation phase | 9.435 s | 7.419 s |

| Output download + validation/import | 6.566 s | 6.847 s |
| Modal-reported GPU-container startup | 3.452 s | 2.864 s |
| Modal-reported input execution | 129.206 s | 126.168 s |
| Measured GPU function body | 126.030 s | 123.040 s |
| Resource-rate estimate, excluding unmeasured startup/network/storage | $0.026832 | $0.026218 |
| Detected events | 1,594 | 1,605 |
| SVG pages | 3 | 3 |

The repeat was 5.840 seconds (3.81%) shorter. The two runs used **different GPU
containers**, consistent with the two-second idle window. Both reused the same
dependency image and model Volume. The main benefit of preparation is avoiding
dependency installation and model downloads on every cold container; it does not
remove the inference work or guarantee a large first/repeat difference after both
jobs already have prepared dependencies and weights.

The production pipeline retains Demucs `--shifts 1`, which samples a random input
offset. The observed detection counts differ by 11 (0.69%); byte-identical output
is not claimed. No annotated reference score was used, so this verifies runtime,
transfers and artifacts rather than transcription accuracy.

```text
CPU preparation rate = 2 × 0.0000131 + 8 × 0.00000222 = $0.00004396/s
GPU worker rate      = 0.000164 + 0.00004396          = $0.00020796/s
```

Those per-run values exclude unmeasured startup/preflight, image builds, network
and storage. They are estimates, not exact per-call invoices.

The provider usage snapshot reported **$0.08732365** for this entire qualification:
image build, CPU preparation, diagnostic/failed attempts, two full transcriptions,

quantized and performance MIDI files decoded with `pretty_midi`. The first SVG page

The live function's image ID still matched the published and full-benchmark image.
This short smoke is separate from the full-track comparison and its cost is included

Final API checks showed zero queued/running jobs and zero active containers for
both preparation and GPU transcription. The temporary job Volume contained zero
files; model weights remain in their persistent Volume for subsequent requests.
The application default remains local when `DRUM_EXECUTION_BACKEND` is unset; the
deployment environment explicitly selects Modal. There is no user-facing engine
selector.

## Integration fixes found by actual execution

- Keep `UV_CACHE_DIR` outside `/models`: the Modal uv launcher otherwise populated
  the mount point before the model Volume could be mounted.
- Handle the installed SDK's built-in `TimeoutError` during asynchronous call polling.
- Create the progress Dict on the client before polling a first-ever GPU job.
- Separate named image publication from app deployment and refuse to overwrite a
  version tag that already references a different image.

Local verification after these changes: 173 Python tests passed, Ruff lint/format
checks passed, and the real remote artifact checks above passed. Earlier frontend
validation for the engine status changes passed type checking, 45 unit tests and
45 browser tests; the named-image change did not modify frontend files.
